# 画布与排版规范（移动端竖版）

本文件是画布尺寸、字号、安全区、中文字体排版的权威来源。生成任何卡片前先读它。
所有数字都以 **1080×1440（3:4）** 为基准推导，其它画布按同比例换算（见 §1.2）。

---

## 1. 画布

### 1.1 三种画布

| 画布 | 像素 | 用途 | 备注 |
| --- | --- | --- | --- |
| `3:4`（默认） | 1080×1440 | 知识卡片、公众号、小红书、PDF 阅读 | 信息密度与手机可读性平衡最好 |
| `9:16` | 1080×1920 | 手机全屏 story、竖屏播放 | 上下留白更多，内容需更少 |
| `1:1` | 1080×1080 | 朋友圈方图、IG 方图 | 高度有限，只适合短内容 |
| `16:9` | 1920×1080 | 传统投影/横屏分享（非移动场景） | 只在用户明确要求时用 |

**默认用 3:4。** 除非用户说明发布平台或明确要求其它比例。

### 1.2 换算比例：一切以宽度为基数

竖版画布的排版尺寸**只跟画布宽度绑定**，与高度无关（高度只决定内容容量）。

```
基准宽度 W = 1080px。以下所有 px 值 = 基准值 × (实际宽度 / 1080)。
例：9:16 画布同为 1080 宽 → 字号不变，只是内容容量更大；
    1:1 同为 1080 宽 → 字号不变，容量更小；
    16:9 为 1920 宽 → 所有字号 × 1.78。
```

**容量规则**：高度变小时**减内容、不减字号**。永远不要为了塞内容把字号调小。

## 2. 安全区与边距（1080×1440 基准）

```
┌─────────────────────────────────┐
│  ↑ 上边距 96–110px               │
│  ← 左右边距 96px →               │
│                                 │
│        内容区最大宽 888px         │
│        （1080 − 2×96）           │
│                                 │
│  ↓ 下边距 88–100px               │
└─────────────────────────────────┘
```

- 左右边距：**96px**（范围 88–104px，全 deck 统一）。
- 上下边距：**96px**（底部可收窄到 88px，顶部可放宽到 110px 留呼吸）。
- 页脚元素（页码、署名）放在底部边距区内，与正文保持 ≥48px 间距。
- 角标/装饰可以**出血**（越出画布），但文字和主体内容永不越界。

## 3. 字号阶梯（1080 宽基准）

| 角色 | 字号 | 行高 | 字距 | 用途 |
| --- | --- | --- | --- | --- |
| `display` 封面大字 | **112–150px** | 1.15–1.25 | 中文 0 / 拉丁 -0.02em | 封面主标题，一行 ≤8 字 |
| `h1` 卡片标题 | **68–84px** | 1.28–1.35 | 中文 0 / 拉丁 -0.01em | 每张卡的主标题 |
| `h2` 小节标题 | **48–58px** | 1.35–1.45 | 0 | 卡内分区标题 |
| `body` 正文 | **36–42px** | 1.65–1.8 | 0 | 常规内容，主力字号 |
| `body-sm` 次要正文 | **30–34px** | 1.6–1.7 | 0 | 注释、脚注式说明 |
| `meta` 标签 | **24–28px** | 1.4–1.5 | 拉丁 +0.08~0.3em | kicker、页码、署名、来源 |
| `stat` 大数字 | **96–160px** | 1.0–1.15 | 拉丁 -0.02em | 数据卡数字 |

**手机可读性判据**：任意文字在手机（~390pt 视口宽）上的等效字号 = `px ÷ 2.77`。
- 正文 38px → 等效 13.7pt ✅
- **正文低于 32px（等效 <11.5pt）即判定不合格** —— 减内容，不要减字号。
- meta 文字可以到 24px（等效 8.7pt），但只用于非关键信息（页码、来源）。

**阶梯纪律**：同屏至多出现 3 个字号档位。字号越多，画面越散。

## 4. 行宽与内容容量（按 888px 内容区推）

**中文**（全角字符宽 ≈ 1×字号）：

| 字号 | 一行最多 | 建议一行 | 视觉行数上限 |
| --- | --- | --- | --- |
| h1 76px | 11 字 | 6–9 字 | 2 行 |
| body 38px | 23 字 | 16–20 字 | 5–7 行/卡 |
| body-sm 32px | 27 字 | 18–22 字 | 6–8 行/卡 |

**内容容量硬上限**（3:4 全屏卡，超了就拆卡）：

- 封面卡：主标题 ≤14 字 + 副标题 ≤24 字。
- 要点卡：标题 ≤12 字 + **3–5 条**要点，每条 ≤26 字（含标点）。
- 正文卡：整卡正文 ≤180 字。
- 对比卡：两栏各 ≤80 字。
- 任何卡：同屏不同文本块 ≤4 个。

**中文行长的经验值**：一行 16–22 字最舒适。超过 24 字，眨眼换行会累。
段落间用空行或 0.5–0.7em 的段间距区分，不要靠首行缩进（移动端缩进不友好）。

**大字（display / statement）的断行纪律**（实测教训）：
- 一行 **6–9 字**；整块 **最多 4 行**；超过 4 行 → 精简文案或降一档字号。
- 断行必须用 `<br>` **手动控制**，不要让浏览器自由折行（会出现只剩 1 个字的孤行）。
- 大字块不要混排"主句 + 从句"两种语速 —— 拆成"大主句 + 小补句"两个元素
  （小补句用 55–65% 透明度或降两档字号），层次比单块硬断更清晰。

## 5. CJK 排版规则（重要，逐条遵守）

1. **行高比拉丁大**：中文正文行高 1.65–1.8（拉丁 1.4–1.5 不够）。标题 1.25–1.45。
2. **字距**：中文正文与标题 `letter-spacing: 0`（中文自带字面间隙，再加就散）。
   仅两种情况例外：
   - 大标题需要更强整体感时 `-0.01em ~ -0.02em`（轻微收紧）；
   - 拉丁大写标签 `+0.08em ~ +0.3em`（仅限纯拉丁文本）。
3. **不要对中文用**：`text-transform: uppercase`（无效果且破坏某些布局）、
   `font-style: italic` 做强调（中文伪斜体很丑 —— 用颜色/字重/衬线切换代替）。
4. **中文标点**：用全角标点（，。：；！？「」——）。破折号用 `——`（两个全角）。
   数字与英文用半角。
5. **中英混排**：中文与英文/数字之间插入一个半角空格（`字 100 个` 而非 `字100个`）。
   这是最有效的"排版精致感"来源之一。
6. **强调手法优先级**：颜色 > 字重（+200） > 衬线/黑体切换 > 下划线。
   不用斜体、不用纯加粗堆叠。
7. **避免孤行**：标题最后一行只剩 1–2 个字时，手动 `<br>` 调整断行位置。
8. **标点悬挂**：行首避免出现 `，。` 等收尾标点（中文引擎多会自动处理；
   手工排版时若出现，把断点前移一个词）。

## 6. 字体策略

### 6.1 三层字体栈

每个设计都用三层定义字体（在 CSS 中体现为栈）：

```css
--font-display: "<风格显示字体>", "Noto Serif SC", serif;      /* 标题/大字 */
--font-body:    "<风格正文字体>", "Noto Sans SC", sans-serif;   /* 正文 */
--font-mono:    "<风格等宽字体>", ui-monospace, monospace;      /* 标签/页码 */
```

- **显示字体**：由所选风格决定（见 style-presets.md / bold-styles.md），
  负责"性格"；中文内容由 `Noto Serif SC` 或 `Noto Sans SC` 接住。
- **正文**：同上，中文兜底 `Noto Sans SC`。
- **标签**：小号全大写拉丁串、页码、署名用等宽或窄体。

### 6.2 中文字体：两级来源

**基础级（永远可用，优先兜底）**——Google Fonts 的思源家族：

| 字体 | 气质 | 适用风格 |
| --- | --- | --- |
| `Noto Serif SC` | 宋体/衬线，庄重文雅 | 文学、学术、编辑风、所有"衬线气质"风格 |
| `Noto Sans SC` | 黑体/无衬线，干净现代 | 现代、专业、几乎所有无衬线风格 |
| `Noto Serif SC` 900 | 极粗明朝体，冲击力 | 封面大字、有力度的标题 |
| 系统兜底栈 | 无网络时保底 | `"Microsoft YaHei", "PingFang SC", "Source Han Sans SC", sans-serif` |

**选装级（个性字体，Phase 2b 让用户挑）**——15 款精选开源字体，
含明朝（汇文明朝体/京华老宋体）、仿宋（朱雀仿宋）、楷体（霞鹜文楷/月星楷）、
黑体（得意黑/霞鹜漫黑/猫啃什锦黑）、圆体、手写、等宽、像素、标题美术。
**完整清单、许可、CDN 加载代码见 `font-library.md`**（唯一数据源，不要临时引入未验证字体）。

**加载方式**（写进 HTML `<head>`）：

```html
<!-- 基础级：Google Fonts -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Noto+Serif+SC:wght@400;700;900&family=Noto+Sans+SC:wght@300;400;500;700&display=swap" rel="stylesheet">

<!-- 选装级：中文网字计划（jsDelivr）——只引被选中的字体 -->
<link rel="preconnect" href="https://cdn.jsdelivr.net">
<link href="https://cdn.jsdelivr.net/npm/@chinese-fonts/<包名>@<版本>/dist/<目录>/result.css" rel="stylesheet">
```

- **字体不内置**：联网按需下载；渲染缓存（`_render-cache/`）会保留已下载的字块。
- 只加载真正用到的字重；中文 webfont 按 unicode-range 分片，一屏卡片 ≈100KB–1MB 字块。
- 每个字体名后**必须**带兜底栈（`"Noto Serif SC", serif` 等），断网时优雅回退。
- **渲染前必须联网**（首次下载字体）；之后浏览器缓存命中，渲染稳定且快。

### 6.3 字号/字重的常见错误

- ❌ 中文用 300 细体做正文 —— 手机上发虚。正文用 400，标题用 700/900。
- ❌ 用 `font-weight: bold` 让中文从 400 跳到 700+（Noto 无 500 时浏览器会合成粗细）——
  显式加载需要的字重。
- ❌ 拉丁显示字体（如 Archivo Black）直接套中文 —— 中文回退到系统黑体，气质断裂。
  中文必须显式配 Noto Serif SC / Noto Sans SC。

## 7. 反模式清单（生成时自查）

- ❌ 一屏塞两个观点（相关内容不同卡）。
- ❌ 正文字号 <32px 或行高 <1.6。
- ❌ 中文字距 >0.02em / 使用斜体 / 使用 uppercase。
- ❌ 一卡超过 4 个文本块、超过 5 条要点。
- ❌ 装饰元素压过内容（不透明度 >30% 的大面积装饰、遮挡文字的图形）。
- ❌ 依赖动画才有终态（渲染是静态快照，元素必须静态即完整）。
- ❌ 纯白 `#ffffff` / 纯黑 `#000000` 做大面积底色（用带色偏的纸白/墨黑，更高级）。
- ❌ 页码写错（如 `03 / 08` 而实际共 10 张 —— 页码由脚本自动填，见模板）。
